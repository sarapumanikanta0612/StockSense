# StockSense Team Rules

Before coding, first inspect TEAM_CONTEXT.md and the existing repository. Understand the current architecture and other developers' responsibilities before making changes.

1. This is ONE shared StockSense project.
2. Four developers work simultaneously.
3. Each developer has a separate responsibility.
4. Never assume another developer's work is complete.
5. Read `TEAM_CONTEXT.md` before starting work.
6. Read the existing code before modifying it.
7. Do not rewrite working code unnecessarily.
8. Do not create duplicate functionality.
9. Do not change another developer's feature area without coordination.
10. Do not invent APIs, routes, database structures, or technologies.
11. Keep changes limited to the assigned task.
12. Communicate cross-team dependencies clearly.
13. Every developer must commit and push meaningful work according to the hackathon's hourly Git requirement.
14. The `main` branch must remain stable.
15. Do not force-push.
16. Do not delete another developer's work.
17. Before making shared changes, communicate with the team.
18. Update `TEAM_CONTEXT.md` when an important shared decision or interface changes.
19. Test changes before committing.
20. Never sacrifice existing functionality just to complete a new feature.
